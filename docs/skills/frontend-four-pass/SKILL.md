# 前端四向精简

在既有产品中减少视觉与文字噪声，让用户更快找到输入、结果与下一步。优先延续品牌，按各页面任务调整结构，不把不同业务强行做成同一个模板。

## 改动边界

- 先确认目标页面、现有设计规范与可编辑文件。默认只改 HTML、CSS、展示组件及显示文案。
- 保留接口路径、字段、参数转换、事件绑定、请求编号、确认步骤、轮询、恢复、下载和校验行为；不改后端、提示词、工具、模型决策或业务状态含义。
- 隐藏技术详情可用可展开区域，但错误、待确认项、费用及未完成原因不能被折叠掩盖。保留标签、焦点、键盘访问和状态播报。
- 先截图和记录现状，再修改。用版本差异或文件摘要验证业务代码没有变化。不要因一次展示优化重新设计业务流程。

## ① 文案

删除复述标题、按钮或明显操作的说明；同一信息在最贴近决策的位置说一次。用具体短句说明“需要什么”“发生什么”“接下来怎么办”。保留必填条件、单位/时区、费用规则、错误恢复、确认边界，以及会影响用户判断的真实/模拟模式区别。不要把“保存草稿”缩写成“发布”，不要把“未完成”美化成成功。

标题命名任务，按钮命名动作，空状态只说明尚无结果和必要前提。演示原理和详细例子优先放入手册，操作页不重复教程。手册可以详细，但步骤引用的按钮名称必须与界面一致。

## ② 配色

盘点已有颜色，优先沿用品牌色；定义少量语义 token：页面/表面/弱背景、主/次文字、分隔/控件边框、主操作/悬停/焦点、成功/警告/错误。相同角色使用同一 token。

若缺少体系，可参考 Radix Colors 的背景、边框、文字、交互状态分工，不必引入依赖或替换现有品牌。状态同时用文字或图标表达，不只靠色彩。正文对比度目标至少4.5:1，必要控件边界和焦点至少3:1；检查实际前景背景组合，不凭肉眼猜。

## ③ 字号

主要字号控制为3–4档，例如14px辅助、16px正文、20px区块/指标、32px页标题。同级内容同字号，靠字重、颜色、行距与间距区分主次。正文与输入保持易读，长ID/JSON允许换行或局部滚动，不缩字硬塞。移动端优先改布局与留白，保留字号层级；必要的无障碍放大不受档数限制。

## ④ 装饰

移除没有信息含义的左侧色条、图标占位、阴影和重复卡片嵌套。用留白与轻分隔组织内容；同类容器、输入和按钮使用一致圆角。浮层可用阴影，普通卡片通常不需要。确实表示风险/状态的色条可保留，但必须有文字说明。

## 验证与交付

- 按“输入→结果→下一步→历史/详情”检查任务结构；不必改变所有页面的顺序。
- 在桌面、窄屏、键盘操作和放大状态检查页面；检查焦点、长文、空状态、成功、错误/待确认、折叠内容和手册。
- 运行现有相关浏览器回归，核对控制台/网络错误；仅为实际风险补验证，避免为静态文案编造大量单测。
- 保存前后截图及简短说明：四个方向各改了什么、哪些功能已验证、有哪些限制。如有运行边界，应在结果中准确注明。
- Skill不授予发布或外部写入权限；沿用会话中已有授权。只有任务要求安装时才写入技能目录，否则按用户指定位置交付。
