# 方案与动作协议

模型循环：search_materials(query) → submit_script(title, scenes) → estimate_duration() / check_rules() → 根据实际观察修改并复查 → finish(outcome)。工具错误、空结果、超长、规则风险均返回给模型。允许模型选择不同工具顺序，但完成必须当前版本双检查通过。

每个分镜包含 source_id、fact_id、voiceover、visual、seconds。字幕复用 voiceover，避免出现第二份未经检查文案。标题、旁白和画面说明均检查；只给素材 ID 不能自动放行虚构事实。每次编辑产生新版本并清除旧检查；检查结果绑定脚本 hash 与资料版本。检索新资料也使规则检查失效。

SQLite 持久化原请求、素材版本、检索状态、脚本修订、检查结果、工具尝试和结果。同 ID 不同输入拒绝；同一任务使用有期限租约避免并发写入。模型步数默认 16，上限触发明确未完成，保留草稿与检查。单次模型请求最多90秒，租约120秒。

真实模型继续使用本机 Ollama qwen2.5:7b-instruct，无需 API Key。模型动作由真实推理产生，工具是本地合成实现；Mock 仅用于流程验证。Python 标准库原生循环便于评审核对，不为框架名称引入无必要依赖。

阶段：需求/原型 → 最小真实循环 → 五必验 → 事实与版本边缘强化 → Web 编辑复查与浏览器 → 实际证据、五篇文档、最终 CI。

## 实测后增加的执行约束

首轮小模型在已有草稿上反复传错估算参数；JSON 对象模式本身不能保证工具契约。改为标准 JSON Schema 约束字段、动作名及参数形状，并用状态阶段控制可用工具：未检索到来源时检索/请求补充；无稿时提交/继续检索；当前版本缺检查时运行缺少的检查；两项已检查且不通过时修订/明确停止；已就绪时结束。框架骨架是预设的，查询与修订内容是模型生成的，实际工具结果反馈后再决定。

模型能够选择停止，不保证一定生成最佳脚本。真实超长样例将3个镜头删成2个并改为各10秒，复估20秒；Mock 的参考修订为10/9/9共28秒。不是运行时把模型修改强制改成固定答案。

模型上下文保留当前输入、已检索事实、当前脚本、精简的时长/风险检查与最近工具观察；完整逐镜头产物、检查和修订保存在 SQLite/Trace。缺数据守卫、手工编辑复查与 Mock 明确不作为真实模型路径。

## 网页编辑协议

POST /api/jobs 提交 request/catalog/mode/max_steps，后台运行、GET /api/jobs/{id} 轮询。POST /api/review 接收已有 job_id 与用户 script，复制原输入/资料、建立新请求后运行确定性的 ReviewModel（mode=review）。它只调用业务检查，不做改写；随后用户显式继续才调用原先选择的生成模式。相同请求修改主题、目标或资料拒绝，网页编辑复查自动新 ID。

服务仅绑定127.0.0.1，校验Host、Origin、会话令牌和256KB体积；限制100条内存任务。业务状态、修订和实际尝试在SQLite；运行Trace可下载。单机示例服务没有生产账户认证。
