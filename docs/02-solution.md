# 方案与动作协议

模型循环：search_materials(query) → submit_script(title, scenes) → estimate_duration() / check_rules() → 根据实际观察修改并复查 → finish(outcome)。工具错误、空结果、超长、规则风险均返回给模型。允许模型选择不同工具顺序，但完成必须当前版本双检查通过。

每个分镜包含 source_id、fact_id、voiceover、visual、seconds。字幕复用 voiceover，避免出现第二份未经检查文案。标题、旁白和画面说明均检查；只给素材 ID 不能自动放行虚构事实。每次编辑产生新版本并清除旧检查；检查结果绑定脚本 hash 与资料版本。检索新资料也使规则检查失效。

SQLite 持久化原请求、素材版本、检索状态、脚本修订、检查结果、工具尝试和结果。同 ID 不同输入拒绝；同一任务使用有期限租约避免并发写入。模型步数默认 16，上限触发明确未完成，保留草稿与检查。单次模型请求最多90秒，租约120秒。

真实模型继续使用本机 Ollama qwen2.5:7b-instruct，无需 API Key。模型动作由真实推理产生，工具是本地合成实现；Mock 仅用于流程验证。Python 标准库原生循环便于评审核对，不为框架名称引入无必要依赖。

阶段：需求/原型 → 最小真实循环 → 五必验 → 事实与版本边缘强化 → Web 编辑复查与浏览器 → 实际证据、五篇文档、最终 CI。
