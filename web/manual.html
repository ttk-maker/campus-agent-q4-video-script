分镜脚本使用手册

1. 启动与入口

在项目目录运行 py -3.10 -m src.web，打开 http://127.0.0.1:8769/。模型端点 localhost:11434/v1 是 API 前缀，不是网页；直接浏览可能返回 404。

2. 第一次创作

  1. 选择“正常生成”，填写主题、受众、平台、目标秒数与风格。目标时长是上限，不要求填满。
  2. 先用离线演练熟悉流程。真实模式需启动 Ollama，并准备 qwen2.5:7b-instruct；本机无需 Key。
  3. 点击“生成 / 优化脚本”。查看每个分镜的画面、旁白/字幕、素材 ID、事实 ID、估算起止时间和原文支持状态。
  4. 总时长仅为启发式估算；录音、剪辑后仍需实测。网页不生成视频，也不实际发布。

3. 修改与复查

展开“编辑脚本并重新检查”，修改 JSON 中的标题、镜头或秒数。编辑时上方检查属于旧的已提交版本，尚未覆盖未提交文字。点击“检查我的修改”创建新请求并执行检索、时长和规则工具，不调用模型改写。

若添加“效率提升80%”而素材只说“支持字幕”，即使填写 P01，检查仍会拒绝。修改后的草稿会保留并显示未就绪。随后可点击“让 Agent 继续处理”，由所选模式根据检查结果修正。

当前事实策略保守：旁白需与引用事实原文匹配（仅忽略汉字之间空白及有限句末陈述/感叹标点；保留英文词边界、句内标点、问号和单位上标）；标题和画面说明用品牌许可短语。来源文本不支持的自由改写会报风险。编辑 JSON 可增加/删除/排序镜头；字幕直接采用已检查的旁白。

4. 演练场景

  • 38 秒草稿：已有镜头 14、12、12 秒，工具先估算，再由模型缩短、重新估算与查规则。离线参考修订为 10、9、9 秒。
  • 无素材：允许改写查询或请求补充，不能从模型记忆捏造产品事实。
  • 工具失败一次：离线首轮停止，点击继续可恢复；真实模型也可能同轮重试。
  • 无依据80%结论：先展示实际风险，模型可修订后复查。
  • 仅1秒：旁白语速下限可能使目标不可满足，不能只改小 seconds 就宣称通过。

5. 状态与恢复

“已完成”要求当前版本时长和规则检查均通过。“待补信息”“执行失败”“无法满足”“达到步数上限”都不是完成。脚本是否已检查与 Agent 是否完成收尾分别显示。

输入或资料改变应生成新 ID；同 ID 改输入会拒绝。已有成功脚本同输入重复执行直接复用。SQLite 保存业务状态和修订；浏览器导出包含输入、输出与 Trace。Web 内存只保留最近100次任务，服务重启后可用原输入恢复业务任务，完整证据应及时下载。

6. 时长口径

每镜头：max(停留秒数, 向上取0.1秒(有效字符数 / 风格语速 + 0.5秒停顿))；镜头间再加配置的转场秒数。简洁/活泼/沉稳语速默认 4 / 4.5 / 3 字符每秒。空格与普通句末标点不计字符，数字附近标点和正负号保留，英文逐字符估算偏保守。字幕展示默认与镜头同长。

工具估算以真实脚本文字计算；模型不能自行填一个总时长覆盖计算结果。来源 ID、时长分镜与规则分镜按相同序号对应。
